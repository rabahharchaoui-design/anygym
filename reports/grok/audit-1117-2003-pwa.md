# Grok pwa audit

- MAJOR vite.config.ts:157 — Demo photos are CacheFirst in `exercise-photos` at stable paths `ex/<id>/0.webp` and `ex/<id>/1.webp` (candidate photos the same way at vite.config.ts:168). `src/lib/photoWarm.ts:36` leaves any URL the cache already holds. `cleanupOutdatedCaches` (vite.config.ts:174) only removes old Workbox precache names, so an app update keeps these caches. The catalog build writes those same paths again (`scripts/build-catalog.ts`). After that update, a phone that already warmed or opened an exercise still shows the previous picture, online and offline. A corrected movement stays on screen, and the review grid can still show the old candidate photo. Smallest fix: put a new version in the photo URL when the bytes change, the same rule already used for the 3D icons, so both the service worker and `PHOTO_CACHE` store the new file.
- MINOR src/screens/TodayScreen.tsx:224 — An update is held while a run is open, and the Update ready chip stays on Today beside that run. Tapping it runs `applyUpdate()`, which returns false for the run, and the toast says "Finish your workout first, then update." The user is mid run and has no workout to finish, so the update stays stuck. Smallest fix: when the recheck finds a run, say "Finish your run first, then update."
- MINOR src/hooks/usePhotos.ts:19 — On gym Wi-Fi with no internet, `navigator.onLine` stays true, so every demo is drawn as a network image (`src/components/exercise/FormDemo.tsx:36`) with no error fallback. The hero is a broken picture, and "Photos show when you are back online" stays hidden because that line runs only when `photos.kind` is `none` (`src/components/exercise/ExerciseSheet.tsx:37`). Smallest fix: on a failed image load, draw the empty frame, the same as the offline path.
