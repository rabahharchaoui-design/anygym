# Grok run audit

- MAJOR src/hooks/runEngine.ts:193 — A run killed mid-way comes back paused and `attach()` starts the GPS watch with the replay guard unset. `replayOf` is set only in `rewatch()`, and that does not run while the run is paused. Tap Resume and the first callback can be the cached spot from before the kill. Its timestamp is older than 5 seconds, so it is stamped as now and starts a new piece of the line there. Real fixes from where you actually are are faster than 8 m/s and are dropped until the 15 second gap, and that gap adds no distance. Simulated: 180 m already run, reopen, Resume 1 second later, then the cached spot, then 20 seconds of jogging 300 m away at 3 m/s. The saved run grew by about 7 m, to 187 m, with a pause and an unbridged gap, and the clock took the 15 second gap credit (moving time 77.5 s). The reload test sends that cached callback 5 seconds after Resume, which is long enough for the 5 second timer to arm the guard, so this window stays green. Smallest fix: before `startWatch()` on the restore path, set `replayOf` to the last saved raw fix (`tracker.raws`, exact match) so that first callback is dropped whether it arrives before or after Resume.
- MINOR src/screens/run/RunStart.tsx:125 — The start map keeps the last dot for every GPS state except "denied", and the dot is labeled "You are here". Get a fix on the sidewalk, then go indoors until the watch times out: the chip says "No GPS signal" and the dot stays on the sidewalk. Leave the app for half a minute and come back: the chip says "Finding GPS" and the dot is still on the old corner. Smallest fix: pass the fix to the map only when the status is good or weak.
