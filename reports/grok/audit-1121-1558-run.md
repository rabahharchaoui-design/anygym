# Grok run audit

- MAJOR `src/hooks/runEngine.ts:178` — Locking the phone or switching apps restarts GPS with no replay guard (the guard is only set on the 15 s rewatch at `src/hooks/runEngine.ts:169`). The run stays active. The first callback is often the last cached spot, and `fixTime` (`src/lib/run/live.ts:135`) stamps anything older than 5 s as now. Run at 3.5 m/s with about 10 m accuracy, open Music for 40 s (140 m), then come back: that cached spot is saved as a 0 m gap, the real fixes are faster than 8 m/s and are dropped, and the gap about 16 s later is roughly 196 m, which is over 8 m/s after accuracy, so it adds no distance. The clock still takes 15 s for each of those two gaps. Smallest fix: set `replayOf` from `lastRaw` before `startWatch()` in `onVisibility`, the same way `every5s` does.
- MAJOR `src/screens/run/LiveRun.tsx:33` — Auto-pause hides a dead GPS signal. `inGap` (`src/lib/run/liveClock.ts:56`) is only true while the clock is still counting, and auto-pause stops the clock, so the note stays "Auto paused · move to go on". Stopped at a light, already auto-paused, then GPS drops under a bridge: you run off and the distance stays frozen with that note for as long as the signal is gone. A hole over 5 minutes then adds none of that distance when the signal returns (`src/lib/gps/tracker.ts:216`). Smallest fix: if the run is not paused by hand and the last good fix is older than 15 s, show "GPS lost · time on hold" before the auto-pause line.
