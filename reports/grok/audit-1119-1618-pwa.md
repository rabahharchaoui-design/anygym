# Grok pwa audit

- BLOCKER src/pwa.ts:10 — An update reloads whenever IndexedDB has no open workout and no open run. The 3-2-1 countdown never writes a row (`src/screens/run/RunStart.tsx:88`), and `runEngine.start` only writes one afterward (`src/hooks/runEngine.ts:233`). If that write fails, the run stays on screen and the save is retried, still with no row. Switching back to the app looks for an update; a waiting version then reloads the page. The countdown is wiped. A run whose first save never landed is gone, and the next open has nothing to resume. Smallest fix: treat the countdown and `runEngine`'s in-memory run as active in `activity()`, and call `skipWaiting` only after that check passes at the moment of reload.
- MAJOR vite.config.ts:14 — `photoVersion()` hashes every file in `public/ex/` into one token, and that token is added to every photo URL. Replacing one picture changes every URL. The service worker and the offline lookup only accept the new query, so pictures already in `exercise-photos` are unused. You open the app in the parking lot, it updates and reloads, then you lock the phone and walk into the basement: the background save stops on the way and does not finish with no signal. Today's workout shows empty frames and "Photos show when you are back online" for demos this phone already saved. Smallest fix: hash each photo file on its own and put that token in its URL, so an unchanged photo stays a cache hit.
- MINOR src/hooks/voiceAudio.ts:20 — Every clip URL uses the single pack version in `manifest.json`. Replacing one clip changes all 220 URLs. The old files stay in `run-voice`, and the player requests the new query. You update, open Run, and lose signal before the background save finishes. Every cue misses, and the whole run is spoken by the phone's fallback voice. Smallest fix: put each clip's own hash in its URL.
- MINOR vite.config.ts:173 — The runtime caches set `maxEntries` and leave `purgeOnQuotaError` unset, so a full origin quota does not delete them. New photos and clips cannot be stored, and a run save fails for the whole run while it continues only in memory. Smallest fix: set `purgeOnQuotaError: true` on `exercise-photos`, `candidate-photos`, and `run-voice` so a full disk drops those caches and the run can be written.
