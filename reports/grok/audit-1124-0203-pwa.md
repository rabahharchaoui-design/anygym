- MAJOR src/screens/run/RunMap.tsx:8 — The map library is its own file, fetched only when Run opens, and a failed fetch is a render error. The only error boundary is the app-wide one (src/components/AppErrorBoundary.tsx:17), so that error replaces Today, History, and a workout already on screen with “Something went wrong.” On a first visit the Run screen file is fetched about a second after open (src/App.tsx:53) and the map file is not. The person sees Today, then loses signal before the service worker finishes saving the app (that cache exists only after its download completes, vite.config.ts:211). They tap Run. The Run screen is already in memory and always mounts the map (src/screens/run/RunStart.tsx:131). The map file was never saved, the request fails, and the whole app is replaced. Reload loads the page from the network again, and with no service worker yet that offline reload does not open the app, so they cannot get back to Today until they have signal. A Run screen file that never arrived does the same thing (src/App.tsx:95). The same throw happens after an update takes control and deletes the old cache (vite.config.ts:210) while a workout that started in that moment keeps the old page up (src/lib/pwaUpdate.ts:71): the map file’s old name is gone, so opening Run after the workout crashes the app. Once the new service worker is in control, Reload does open the app. Smallest fix: catch a failed map import inside RunMap and keep the dark placeholder, and catch a failed Run-screen import on the route so the rest of the app stays up. Do not reload while a workout or run is active.
