1. **MAJOR — Resuming a hold can save the wrong duration.**  
   [TimedInput.tsx:54](/Users/rabah/projects/anygym/src/components/load/TimedInput.tsx:54), [SetCard.tsx:77](/Users/rabah/projects/anygym/src/screens/workout/SetCard.tsx:77)  
   Stop at 10 seconds, tap “Start again,” then tap Log set while the timer runs. The parent still holds 10 seconds, so it saves that stale duration and resets the running timer. Violates SPEC 0’s accurate-data rule.  
   **Exact fix:** Expose running state to SetCard and disable logging while running, or stop and capture the current elapsed duration atomically when logging.

2. **MAJOR — A chosen weight or running hold disappears when switching exercises.**  
   [ExerciseCard.tsx:50](/Users/rabah/projects/anygym/src/screens/workout/ExerciseCard.tsx:50)  
   Collapsing an exercise unmounts SetCard and its timer. Returning recreates inputs from the last saved set, losing the pending weight, reps, and elapsed hold. Reloading also loses these drafts.  
   **Exact fix:** Store drafts and stopwatch timestamps by session/exercise outside the conditional card; persist them locally and clear only after a successful log or explicit reset.

3. **MAJOR — Failed deletes look successful and can silently remain in the saved workout.**  
   [undoQueue.ts:23](/Users/rabah/projects/anygym/src/lib/undoQueue.ts:23), [WorkoutScreen.tsx:147](/Users/rabah/projects/anygym/src/screens/workout/WorkoutScreen.tsx:147)  
   The UI hides the set immediately. The queue removes its pending entry before writing, then swallows database failures. Finish can report success with the supposedly deleted set included.  
   **Exact fix:** Propagate commit failures, unhide failed deletions with a retry message, and make Finish wait for all deletion writes—including already-running commits—before counting sets.

4. **MAJOR — Delete is not durable when iOS kills the app.**  
   [WorkoutScreen.tsx:64](/Users/rabah/projects/anygym/src/screens/workout/WorkoutScreen.tsx:64), [undoQueue.ts:34](/Users/rabah/projects/anygym/src/lib/undoQueue.ts:34)  
   During the five-second Undo window, deletion exists only in memory. A process kill need not fire `pagehide`, and asynchronous IndexedDB writes started there are not guaranteed to finish. Deleted sets can reappear.  
   **Exact fix:** Delete transactionally immediately and retain a durable undo record, or persist deletion tombstones and reconcile them on startup.

5. **MAJOR — Changing the stack step leaves an invalid weight loggable.**  
   [StackSelector.tsx:35](/Users/rabah/projects/anygym/src/components/load/StackSelector.tsx:35), [StackSelector.tsx:128](/Users/rabah/projects/anygym/src/components/load/StackSelector.tsx:128)  
   Select 15 lb, then change the step from 5 to 10. The new list has no selected pin, but the parent still holds 15 lb and Log set remains enabled.  
   **Exact fix:** On step-save, validate the selected pin against the new values. Clear an invalid selection and disable logging until the user picks again; do not silently round it.

6. **MAJOR — Barbell logging always assumes Olympic weight unless the name says Smith.**  
   [exerciseLoad.ts:21](/Users/rabah/projects/anygym/src/screens/workout/exerciseLoad.ts:21)  
   Every other bar uses 45 lb / 20 kg, with no bar selector in the workout. Someone using an EZ, trap, or women’s bar can save an incorrect total. The EZ/trap first-use machinery exists but is unreachable through this field. Violates SPEC 0 and 5.3.  
   **Exact fix:** Pass an explicit equipment/bar ID into the input, offer bar selection where ambiguous, and wire unknown EZ/trap weights to their existing first-use prompts.

7. **MAJOR — Modal sheets do not manage focus or provide an accessible close control.**  
   [Sheet.tsx:22](/Users/rabah/projects/anygym/src/components/Sheet.tsx:22), [Sheet.tsx:47](/Users/rabah/projects/anygym/src/components/Sheet.tsx:47)  
   Opening a sheet leaves keyboard focus behind it; Tab can reach background actions. The scrim and grabber are not accessible close buttons. Nested sheets also all register Escape handlers, so one Escape can close both.  
   **Exact fix:** Use a modal dialog implementation with initial focus, focus trapping/restoration, inert background content, a labelled Close button, and topmost-only dismissal.

8. **MAJOR — Finishing makes saved sets inaccessible through the UI.**  
   [HistoryScreen.tsx:8](/Users/rabah/projects/anygym/src/screens/HistoryScreen.tsx:8)  
   After “Workout saved,” History still unconditionally says “No workouts yet” and promises finished workouts will appear. The ended workout cannot be reopened to inspect or correct its sets. Data remains in IndexedDB; this is an access failure, not proven deletion.  
   **Exact fix:** Provide a minimal real session list and reopenable set detail now, or hide the unfinished History destination and its false promise until available.

9. **MAJOR — Current Quick workout explicitly contradicts SPEC 20.**  
   [ExerciseCard.tsx:64](/Users/rabah/projects/anygym/src/screens/workout/ExerciseCard.tsx:64), [SetCard.tsx:70](/Users/rabah/projects/anygym/src/screens/workout/SetCard.tsx:70)  
   Unknown exercises require “How do you load this?”, then use an open-ended single-set card with a hardcoded 10-rep default. There are no prescribed set rows or automatic completion/advance. SPEC 20.3 explicitly applies the new flow to Quick workout.  
   **Exact fix:** Supply reviewed exercise metadata, create explicit target set rows when adding an exercise, log through each row’s check, and advance after the final row. PLAN 1.7c acknowledges this is deferred; it remains a current spec violation.

10. **MINOR — Update can be applied while a workout remains active.**  
    [pwaUpdate.ts:23](/Users/rabah/projects/anygym/src/lib/pwaUpdate.ts:23)  
    Automatic updates check activity, but the “Update ready” action calls the reload callback without checking again. Returning to Today during an unfinished workout permits an interrupting reload, potentially losing drafts.  
    **Exact fix:** Recheck active workout/run state immediately before applying any update; retain the waiting chip until both end.

11. **MINOR — Landscape protection required for iPhone is absent.**  
    [Workout.module.css:3](/Users/rabah/projects/anygym/src/screens/workout/Workout.module.css:3)  
    The workout stays in its portrait layout when rotated. iOS ignores the manifest orientation lock, leaving very little vertical room for the active set. No landscape guard exists in the source. Violates SPEC 13.4.  
    **Exact fix:** Add the specified full-screen “Turn your phone upright” overlay for landscape phones while keeping the workout mounted underneath.
