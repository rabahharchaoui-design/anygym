# Review of codex-build-SV2-1128-0318 (18f4110a): MERGE AFTER FIXES

Reviewed Nov 28 by Claude (review agent). The branch has a full-suite PASS for its exact head
(.loop-tools/verify/codex-build-SV2-1128-0318.txt) and merges cleanly into s4-run, but it lets stale or
evidence-less drafts come back as duplicate pending rows. It is not merged. Fixes A to F below are
Codex's fix round (queued Nov 29). Merge order still applies: SV2 merges after SV1 and after Grok's review.

## Fixes

**A. A proven-superseded draft comes back as a pending row.** `src/lib/setTable.ts:128-130`
(`reconcileRows`) now consumes a draft only when its payload fingerprint equals the receipt's; the "or
proven superseded" branch is gone. A stale draft (rev 1, 8 reps) against committed rev 2 (10 reps)
returns `r~1` with 8 reps, a pending duplicate that can be logged again. The test
`src/screens/workout/__tests__/fixes-1.7i.test.ts:224-236` was changed so the stale rev 1 draft has the
same payload as the committed one, which hides this.
Fix: restore supersession when the draft and the receipt provably share a lineage (same `op` or
`submitted` mark, older `rev`), and add the different-payload test back.

**B. A set with no payload evidence keeps its draft.** `setTable.test.ts:278-280` replaced "used up"
with "keeps the draft"; `reconcileRows` returns `a~1`. For a committed set with no `fps` entry (no load,
or a pre-2.0l receipt) the next check logs a duplicate.
Fix: restrict this to genuinely unknown evidence, or prove with a test that the duplicate cannot show.

**C. Clean cached drafts that IndexedDB lacks are deleted.** `src/lib/drafts.ts:44-60` removed the
`!validDraft(theirs)` fallback, and the `on('complete')` hook (lines 58-62) deletes clean memory rows
missing from IndexedDB. A draft that exists only in localStorage and was never marked dirty is dropped,
and the next `mirror()` rewrites localStorage without it. No test covers the never-mirrored case.
Fix: explicit deletion markers (tombstones) for removals, plus a test where a clean localStorage-only
row survives a merge.

**D. `hydrated` is set after every merge, even when localStorage works.** `drafts.ts:62`
(`hydrated.set(s ?? NO_STORAGE, store)`) is meant only for the "localStorage refused" state. While it is
set, `mergeFromStorage` returns early (another tab's changes are not picked up) and `mirror()` returns
false until the next `persistRows` clears it.
Fix: set it only when localStorage is absent or failed, with a test.

**E. Legacy receipts are trusted without checking.** `src/screens/workout/rowLog.ts:217`
(`fp: sub.fp ?? fp`) treats a receipt without a fingerprint as matching this draft, so `mine()` falls
back to revision equality alone, which SV2 forbids.
Fix: use `UNKNOWN_FP` there.

**F. Smaller points.**
- `src/screens/workout/rowReceipts.ts:11-14` and 19-22 repeat the same `payloadFp({...})` build: use one helper.
- `setTable.ts` and `setTableWords.ts` import each other (`countModeOf`, `KeptPick`): move both to `setTypes.ts`.
- The `foundation-2.2e.spec.ts` try/catch re-navigation is unrelated to SV2: split it out or drop it.
