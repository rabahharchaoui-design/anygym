1. **Personal data survives diagnostic sanitization.** [diagnostics.ts:9](/Users/rabah/projects/anygym/src/lib/reporting/diagnostics.ts:9) preserves names, notes, formatted phone numbers, and arbitrary URL path segments. For example, `Error: Quentin Privateperson, phone 602-555-1234` reaches automatic crash payloads unchanged. **Fix:** use allowlisted diagnostic messages and script locations; replace arbitrary error text and non-script paths with placeholders before constructing messages, stacks, signatures, or console entries. Regex removal of selected identifiers cannot meet SPEC 24’s privacy guarantee.

2. **Push notifications forward personal text without sanitization.** [handlers.ts:63](/Users/rabah/projects/anygym/workers/anygym-api/src/handlers.ts:63) forwards the feedback’s first line directly to ntfy; lines 68 and 87 also forward crash and stored report text. Names, emails, or phone numbers entered in a report therefore reach ntfy, violating SPEC 24’s “no personal data” requirement. **Fix:** apply a shared privacy-safe notification formatter to all three paths; use a generic report reference whenever free text cannot safely be included.

3. **A previous sheet’s screenshot can attach to a new report.** [ReportProblemSheet.tsx:37](/Users/rabah/projects/anygym/src/screens/settings/ReportProblemSheet.tsx:37) resets state on reopening but never invalidates `pick.current`. Close while image preparation is pending, reopen, and the old operation can populate the new report with the previous screenshot. **Fix:** increment the operation generation on both closing and opening, invalidate pending operations on unmount, and revoke URLs from stale completions.

4. **Receipt handling can strand reports or duplicate them.** [handlers.ts:53](/Users/rabah/projects/anygym/workers/anygym-api/src/handlers.ts:53) claims a receipt, inserts the report, and settles the receipt in separate database operations. Termination after claiming leaves retries returning 409 until the 30-day prune; failure after inserting but before settlement deletes the receipt and lets retries insert another report. **Fix:** perform receipt claiming, report insertion/crash update, and receipt settlement atomically in a D1 transaction, with an idempotency key durably linked to the report.

5. **Turning crash reporting off does not stop another open tab.** [preferences.ts:17](/Users/rabah/projects/anygym/src/lib/reporting/preferences.ts:17) caches the preference indefinitely per JavaScript context. Another tab that previously loaded `true` continues capturing and sending after the stored toggle becomes `false`. **Fix:** synchronize preference changes across contexts and read the persisted preference immediately before enqueueing and sending crashes.

6. **Completed request IDs bypass the hourly request limit.** [handlers.ts:44](/Users/rabah/projects/anygym/workers/anygym-api/src/handlers.ts:44) returns completed receipts before calling `takeRate`. Anyone can submit one valid report, then replay its request ID indefinitely without consuming the specified 20-requests-per-IP-per-hour budget. **Fix:** enforce the IP rate limit before receipt lookup and duplicate responses.
