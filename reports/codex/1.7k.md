1. **Privacy leak — [src/lib/reporting/mask.ts:157](/Users/rabah/projects/anygym/src/lib/reporting/mask.ts:157).** `stackRefs()` treats arbitrary line endings as script locations: `Error: alice-smith.js` becomes `alice-smith.js`, which then enters transmitted stacks and signatures. `autoMessage()` also preserves fabricated locations in already formatted messages. This violates SPEC §24. **Exact fix:** restrict locations to shipped script filenames, reject error headers as stack frames, and apply the same validation to preformatted messages in both app and Worker.

2. **Added rows lost on restart — [src/lib/extraSets.ts:51](/Users/rabah/projects/anygym/src/lib/extraSets.ts:51).** When accessing `localStorage` throws, `storage()` returns `null`. Optional chaining skips the write without entering `catch`, and `mirror(null, KEY)` does nothing. Added rows exist only in memory despite available IndexedDB, violating §13.3. **Exact fix:** explicitly persist `durableRow(KEY, value)` to IndexedDB when storage is null; persist a null row for `clearExtraSets()` too. Calling `mirrorValue()` alone is insufficient because it also rejects null storage.

3. **Changing bars rewrites legacy history identity — [src/db/history.ts:72](/Users/rabah/projects/anygym/src/db/history.ts:72).** Legacy sets are classified using today’s exercise settings. Selecting Smith makes `legacyBarOf()` classify every legacy set as Smith—even an Olympic set with a stored 45 lb bar and a gym Smith weight of 0. This corrupts history and progression under §§0 and 6. **Exact fix:** prioritize stored bar-weight evidence, persist resolved legacy `barId` values before changing relevant settings, and keep ambiguous sets out of comparisons rather than guessing.

4. **Legacy Smith sets still receive Olympic records — [src/db/history.ts:191](/Users/rabah/projects/anygym/src/db/history.ts:191).** `workoutRecords()` classifies the workout being evaluated with `load.barId ?? defaultBar`, while earlier workouts use the new legacy resolver. A legacy Smith bench workout therefore compares against Olympic history and can display false records. **Exact fix:** resolve the evaluated sets through `legacyBars()` too, and use that identity when forming the Smith/free-bar groups.
