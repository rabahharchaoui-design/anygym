**14 — cloud lock age.** Confirmed: `cloud_busy` treats a still-taken lock as free after 10,200 seconds. This removes that expiry.

Safety: an observed lock remains respected regardless of its age; a release still clears it. Test by extracting the function into a zsh harness with a stubbed `git log` and checking old “lock taken” and “lock released” subjects. This does **not** add the requested notification, protect against fetch failure or missing lock data, implement a singleton lock, or stop an already-running loop on handoff.

The remaining findings:

- **2 — confirmed:** the four-point start gap can be impossible near the capped pace. The proposed `allowed + 10` run threshold can exceed the 85% cap, so it needs an explicit policy that preserves the hard cap.
- **3 — confirmed:** stale data currently makes `over_limit` return “not over,” and the weekly check can suppress `hold_set`. A 30-second polling guard cannot guarantee a hard 83% ceiling. Probe freshness, missing fields, start limits, and override behavior need to be changed together.
- **5 — confirmed:** prose in the last six lines can trigger a sleep or model switch and bypass the fast-run counter. The tap’s general `status` and windows do not establish that a **Fable-specific** limit occurred, so they cannot safely support the proposed model switch without more evidence.
- **6 — confirmed:** the watcher processes only the newest event, misses the named patterns, and treats a normal final line as evidence of a crash. A cursor must also handle log truncation or replacement and persist completion state; a simple line offset alone is insufficient.
- **7 — substantially confirmed:** several waits and Codex calls lack notifications or timeouts. Some waits have no known end time, so a promised end clock time cannot always be supplied. An alarm on the direct `codex` process also does not by itself prove its descendants stop.
- **10 — confirmed:** Grok can see the guard log before Claude exits. Merely checking for `.usage-stop` or `.usage-hold` is insufficient: the former is moved after a run and an expired hold may remain. A shared, explicit pause state is needed; Codex’s explicitly configured parallel lane also remains a separate path.
- **11 — confirmed:** the numeric-only patterns omit M, D and Q IDs, and both helpers can select the same item. Creating separate report files before returning does **not** atomically claim an item; both can still create one. This needs one shared atomic claim per ID and recovery for abandoned claims.
- **13 — confirmed:** file mtime is used as the reading time, `int()` truncates decimals, and the cap is only checked before a build. Correctly aging the reading requires validating the actual session-record timestamp format; terminating an active build safely also needs process and partial-output handling.
- **14 — additionally confirmed:** there is no loop singleton or handoff check in `run-overnight.sh`. macOS does not generally provide the Linux `flock` command by default, so the suggested command is not portable; a replacement must also survive the script’s `exec` reload and handle stale ownership.

The two diffs use no arrays, `[[ ]]`, or `case` inside command substitution. They have **not** been syntax-checked or exercised here; validate proposed changes with macOS `/bin/bash -n` and `zsh -n` as appropriate before applying them.
