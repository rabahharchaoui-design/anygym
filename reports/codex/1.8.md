1. **Damaged backups can silently erase whole tables.** [src/lib/backup.ts:159](/Users/rabah/projects/anygym/src/lib/backup.ts:159) accepts missing tables; `upgradeTables` replaces them with empty arrays. A schema-v6 backup missing `runs`, `profile`, or `exerciseSettings` therefore passes validation, and Replace deletes that phone data. **Fix:** require every table present in the declared schema; synthesize empty arrays only for tables introduced after that version.

2. **Malformed records pass validation and can break logging after Replace.** [src/lib/backup.ts:105](/Users/rabah/projects/anygym/src/lib/backup.ts:105) accepts gyms without `equipmentWeights`, `stackStep`, or valid bar and plate values. For example, missing `equipmentWeights` subsequently throws in `stackStepFor`/`machineStartFor`, after the original gyms have been deleted. Other checks similarly admit malformed exercise settings and session exercise lists. **Fix:** validate all required fields and nested structures, plus optional fields when present, against their stored types before offering restore.

3. **Orphaned workouts pass validation.** [src/lib/backup.ts:176](/Users/rabah/projects/anygym/src/lib/backup.ts:176) checks only set→session references. A backup containing an active session whose `gymId` is absent passes and replaces the database, leaving a workout that cannot load its gym. **Fix:** also require every session’s gym to exist in the backup; validate session references in counters, submissions, and tombstones, including agreement between each tombstone and its embedded set.

4. **Mid-workout exports omit saved pending sets.** [src/db/backup.ts:30](/Users/rabah/projects/anygym/src/db/backup.ts:30) exports only Dexie tables, while pending weights, reps, running holds, and failed submitted rows live in `anygym-drafts` and its memory cache. Restoring on another device loses those entries, including failed Log set writes awaiting retry. This violates SPEC 9.1’s “Export everything.” **Fix:** persist drafts in Dexie and include them in the same backup snapshot and restore transaction, preserving draft IDs, revisions, submission markers, and stopwatch state.
