1. **P1 — An older save can silently supersede a newer failed edit.** [src/db/mutations.ts:275](/Users/rabah/projects/anygym/src/db/mutations.ts:275)  
   `mem.set()` happens before acquiring the session lock. Two overlapping saves therefore let the first save include the second save’s memory entry in `covered`. If the first lands and the second fails to journal, the first’s receipt hides the newer correction, allowing Finish to discard it. **Fix:** register operations inside the session lock and cover only operations registered before the current operation.

2. **P1 — Storage recovery can erase a draft already saved in IndexedDB.** [src/lib/drafts.ts:232](/Users/rabah/projects/anygym/src/lib/drafts.ts:232)  
   After localStorage rejects a write, `persistRows()` clears the row’s dirty flag without making IndexedDB authoritative for subsequent reads. When localStorage starts working again, editing another row lets `mergeFromStorage()` delete the first row because stale localStorage lacks it; the successful whole-blob mirror then deletes its IndexedDB copy. **Fix:** retain the committed IndexedDB snapshot as the authoritative hydrated state until localStorage receives that merged snapshot successfully.

3. **P1 — Supersession receipts are lost when applying a journaled correction fails.** [src/db/mutations.ts:299](/Users/rabah/projects/anygym/src/db/mutations.ts:299)  
   `covered` exists only in the current call. If `apply()` fails or the app terminates before it commits, Retry calls `apply(e.id, db)` without those IDs. An older held copy remaining in another tab’s memory or unwritable localStorage never receives a receipt and can later overwrite the successfully retried correction. **Fix:** persist covered operation IDs atomically with the journal entry, read them during every apply/retry, and remove held copies only with the successful change and receipts.

4. **P1 — Held operation IDs can collide across tabs.** [src/db/mutations.ts:265](/Users/rabah/projects/anygym/src/db/mutations.ts:265)  
   IDs combine a timestamp with a module-local sequence. Separate tabs can generate the same ID for the same set and kind at equal timestamps. The `e.id !== memId` check then excludes the older operation from supersession, or shared fallback/kv storage replaces one correction with the other. Retry can consequently restore stale values. **Fix:** use a globally unique operation ID, such as `crypto.randomUUID()`, independent of clocks and per-tab counters.
